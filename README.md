## Repository Structure

This repository is organized to keep the web app, backend services, and machine learning tooling separate and easy to understand.

- `frontend/`: Vite + React frontend application source and public assets.
- `frontend/src/`: React application source code.
- `frontend/public/`: Static assets served by the frontend.
- `backend/`: Node backend API server, utilities, and native addon sources.
- `ml/`: Machine learning training, inference, and model tooling.
- `shared/`: Cross-project shared resources, such as protocol buffers.
- `docs/`: Architecture, compliance, and workflow documentation.
- `scripts/`: Helper scripts for local setup, testing, and release workflows.
- `data/`: Sample data and seed data for the project.
- `build/`: Local native build artifacts generated by node-gyp. This folder should not be committed.
- `frontend/dist/`: Local Vite build output. This folder should not be committed.
- `.cursor/`, `.auth.db`: Local editor/agent metadata and auth state. These should not be committed.

**Package management** is centered on npm using `package-lock.json` as the canonical lockfile.

**New contributors**: Start with `docs/CONTRIBUTING.md` for setup, the PR score rubric, and workflow expectations.

**Development workflow** is documented in `docs/WORKTREE_ARCHITECTURE.md`.

## Security Automation

Gauss Aurora includes automated security scanning, compliance gating, and release signing:

**Four Core Automations**:
1. **Dependency Vulnerability Scanning** — Dependabot + npm audit
2. **Secret Detection & Rotation** — TruffleHog + pre-commit hooks
3. **Code Signing & Release Artifacts** — Cosign + SLSA provenance
4. **Security Compliance Gating** — RBAC + headers validation

**Setup (One-Time)**:

## Quality & Testing Automation

Gauss Aurora includes comprehensive quality gates and automated testing:

**Five Core Automations**:
1. **Type Safety & Linting Gate** — TypeScript type check + ESLint
2. **Test Coverage Enforcement** — Unit tests + E2E tests (Playwright)
3. **Build & Release Pipeline** — Auto-versioning + changelog generation
4. **Database Migration Safety** — SQL validation + downtime detection
5. **Performance Regression Testing** — Bundle size + memory + latency monitoring

**Setup (One-Time)**:
```sh
# No setup needed! All workflows active automatically
# Just run these commands before pushing:
npm run quality:full     # Type check + linting
npm run test:all         # Unit + E2E tests
npm run perf:check       # Bundle size analysis
```

**Common Commands**:
```sh
npm run quality:types                    # TypeScript type check (frontend app, Vite config, backend)
npm run quality:lint                     # ESLint checking
```
