GAUSS_ARGO · BUILT LIKE A SPACECRAFT

Connectivity that heals itself.

Gauss watches your mission data. Gauss Argo looks after the machines your team works from: it runs each one the way a spacecraft runs itself. When the network breaks, it works out why, applies the smallest fix, checks that the fix worked, and remembers what worked on each network.

We built it for our own team, who work from phone hotspots and public Wi‑Fi, and now include it for Gauss operators: teams with a paid Gauss plan.

01_WHAT_IT_CATCHES

It tells one broken network from another.

  • No connection at all
  • A Wi‑Fi sign-in page in the way
  • Names that won’t resolve (DNS)
  • A dead proxy, or a background service that has stalled
  • Ports your work needs, blocked
  • A network reading your encrypted traffic: Argo flags it and never turns certificate checks off
  • Traffic leaving from a country your team hasn’t approved
  • Open or weakly secured Wi‑Fi (open, WEP or WPA1), a Mac sharing its files or screen on it, and proxy auto-discovery traps. Argo advises; it never changes your settings.

02_HOW_IT_WORKS

Detect, isolate, recover: the way spacecraft handle faults.

  1. Detect

    Checks the network every minute, with a fuller probe every few minutes.

  2. Classify

    Names the fault, so the fix fits the cause instead of restarting everything.

  3. Fix

    Tries the least invasive fix first. Anything needing an administrator is shown for you to run; it never runs on its own.

  4. Verify and learn

    Checks the fix worked and remembers it for that network, which is recognised by a fingerprint: the raw IP and router address are never stored.

On a Mac, when it can’t fix something, Gauss Argo texts your phone once, then at most every two hours. Each device can also report its state to the Gauss console, so a team can see who is cut off.

03_STORE_AND_FORWARD

Files that arrive, however patchy the link.

Gauss Argo sends files between your team’s devices the way spacecraft send data home: each one is held, forwarded when a path opens and confirmed when it lands. A dropped hotspot, a laptop asleep overnight or a machine that is only reachable in short windows delays a file; it doesn’t lose it.

  • Built on the IETF Bundle Protocol (RFC 9171), the standard for delay-tolerant networking.
  • Signed by the sending device and encrypted end to end to the receiving one (HPKE, RFC 9180). The Gauss hub holds only ciphertext it can’t read.
  • Each file is confirmed by a signed receipt from the device that received it. The sender keeps it until then, and sends it again if the hub ever loses it.
  • No internet at the far end? Copy the queue to a drive and carry it there. Whoever carries it can neither read nor change it.
  • Each device shows its link stability: how much of the week it was connected, how often it dropped and how long it took to come back.
  • Keys are checked on first contact and shown as a short code, so two people can compare them before trusting each other’s files.

Tested in a five-day simulation built from our own hotspot’s drop-outs, with a laptop asleep each night, a machine reachable only in ten-minute passes and a hub that lost its data three times: every file arrived exactly once, with a receipt.

04_BUILT_TO_BE_TRUSTED

Rules it can’t break, enforced in code and tests.

  • TLS verification is never disabled.
  • No administrator action runs automatically.
  • No secrets are written or sent; reports mask anything that looks like one.
  • Files it carries are encrypted before they leave the device; private keys never leave it.
  • No code is fetched at runtime: one program, Go’s standard library only.
  • It runs as you, never as root.
  • Its state files are readable only by you.

05_WHERE_IT_RUNS

Mac today, Linux in a container.

Now

  • macOS, as your own background agent
  • Linux, as a 9.5 MB container (non-root, read-only) for ground stations and edge machines

Not yet

  • Windows
  • iPhone and Android (phones are watched today, not healed)
  • Direct device-to-device transfers (files go through the Gauss hub or a carried drive today)

06_IN_DEVELOPMENT

Next: a private relay.

We’re designing a two-hop relay for internet access: two relays run by different organisations, so that no single company, us included, can link you to your traffic. Gauss Argo would choose the path on each network the way it already does for files: direct first, then your own exit point, then the relay.

It isn’t available yet. It launches only after an outside security review and legal checks. Operators will hear first when it’s ready.
